# Agro Scoring API

Лабораторная работа №1, «Современные интеллектуальные сетевые сервисы».
Автор: Сульповар Михаил Леонидович, МПИ-25-1-1.

## Установка и запуск

Python 3.12 или новее. Команды выполняются из корня проекта.

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload
```

Swagger UI: http://127.0.0.1:8000/docs
OpenAPI: http://127.0.0.1:8000/openapi.json

Для тестирования и проверки стиля:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```

Зависимости зафиксированы по версиям, использованным при проверке. Файлы
requirements-dev.txt включают рабочие зависимости, httpx, pytest и Ruff.

## Структура и зависимости

| Модуль | Ответственность |
|---|---|
| app/main.py | Создание приложения, middleware, логирование |
| app/api/routes.py | HTTP-маршруты, статусы, параметры, Depends |
| app/schemas/prediction.py | Схемы запроса, ответов и ошибок |
| app/models/risk.py | Учебная модель и метаданные |
| app/services/scoring.py | Бизнес-валидация и выполнение прогноза |
| app/repositories/predictions.py | Сохранение, поиск и фильтрация |
| tests/test_api.py | 22 проверки поведения API и модели |
| report/main.tex | Исходник отчета |
| report/images/ | Настоящие скриншоты работающего Swagger UI |

API вызывает сервис, сервис вызывает модель и хранилище. Схемы являются
общим контрактом. Хранилище создается отдельно для каждого приложения.
Сервис не зависит от FastAPI; HTTPException используется только в API.

## Маршруты

| Метод | Путь | Ответ |
|---|---|---|
| GET | /health | 200, состояние процесса API |
| GET | /model-info | 200, метаданные и готовность модели |
| POST | /predict | 201, созданный прогноз; 400/422/503 при ошибке |
| GET | /predictions | 200, новые прогнозы первыми; 422 при неверных параметрах |
| GET | /predictions/{request_id} | 200 или 404 |

`limit`: от 1 до 100, по умолчанию 10.
`risk_level`: low, medium или high; по умолчанию фильтра нет.
Разрешенные регионы: Krasnodar, Rostov, Stavropol.
Все девять полей запроса обязательны; пример находится в report/request.json.
POST возвращает Location и X-Process-Time; остальные ответы также содержат
X-Process-Time (секунды).

## Отличия от исходного main.py

- Логика разделена по директориям и ответственности.
- Добавлено одно учебное правило: температура <5 или >35 повышает риск на 0.05.
- Версия модели 1.1; правила остального скоринга сохранены.
- Результаты возвращаются новыми первыми, фильтрация идет до limit.
- POST создает сохраняемый результат и возвращает 201 с Location.
- Фильтр категории описан Literal; неверная категория возвращает 422.
- Добавлены очистка внешних пробелов, запрет нечисловых бесконечностей,
  изоляция хранилищ отдельных приложений и блокировка словаря.

Модель представляет собой правила, а не обученную ML-модель. Ее оценка
не является калиброванной вероятностью дефолта. Результаты хранятся только
в памяти: перезапуск очищает их, разные workers не разделяют данные.
Запускайте учебный пример одним процессом. Поля area_ha и crop_type
валидируются, но пока не участвуют в расчете, как и в исходнике.

Для ручной проверки 503 установите MODEL_READY = False в app/models/risk.py.
Некорректное тело при этом все равно получит 422, поскольку Pydantic
выполняет структурную валидацию раньше обработчика.
